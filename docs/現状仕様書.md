## 1. アプリ概要（現状）

### 何ができるアプリか
- ORIGAMI GRP のブランドサイト配下にぶら下がる、AI学習コンテンツを提供する**会員制サブスクリプションサイト**
- ログインしたユーザーが、自分の契約プランに応じた動画を視聴できる
- 管理者がユーザーのプランを手動で切替・動画を承認・コンテンツを管理できる

### 対象ユーザー（実態）
- 会員（user / adder / admin の3ロール）
- AIスクール受講者を想定

### 技術スタック（実態）
| レイヤ | 採用技術 |
|---|---|
| フロントエンド | 静的HTML + vanilla JavaScript |
| CSSフレームワーク | 自前 `styles.css` + `member/styles/member-styles.css` |
| ライブラリ | Supabase JS SDK v2（CDN直読み） |
| 認証・DB | Supabase（URL: `gfvnnxuupdmbuxejyfck.supabase.co`） |
| ホスティング | Vercel（mainブランチ自動デプロイ） |
| 決済 | **未実装**（手動運用） |

## 2. ロール体系（実態）

| ロール | 値 | 判定方法 | 権限 |
|---|---|---|---|
| 一般会員 | `profiles.role = 'user'` | profilesテーブル | プランに応じた動画視聴 |
| 動画追加者 | `profiles.role = 'adder'` | profilesテーブル | + `/member/upload.html` で動画申請 |
| 管理者 | `profiles.role = 'admin'` AND `admin_users` に登録 | 二重判定 | + `/admin/` 全機能 |

> ⚠️ admin判定が **`profiles.role` と `admin_users` の二重管理** で散らかっている。

## 7. 認証・アクセス制御フロー（実態）

### 7-1. ログインガード（[auth-guard.js](member/js/auth-guard.js)）
1. ページ読込み時に `body { display: none }` でチラつき防止
2. Supabase セッションを取得
3. セッションなし → `login.html` に強制リダイレクト
4. プロフィール（profiles）を取得
5. **プロフィール未設定**（フリガナ or 英語表記が空）→ 強制で `profile.html` に遷移
6. ページ別の追加ガード：
   - `upload.html` → admin/adder 以外はアラート → `dashboard.html`
   - `dashboard.html` → 名前・ランクバッジ・進捗・お知らせ・おすすめを動的表示

### 7-2. 管理者ガード（[admin-guard.js](admin/js/admin-guard.js)）
1. Supabase セッションを取得
2. セッションなし → `member/login.html` へ
3. `admin_users` テーブルに自分のIDがあるか確認
4. なければ `member/dashboard.html` へリダイレクト

### 7-3. Supabase 接続情報（実態）
- **各HTMLにハードコード**：URL=`https://gfvnnxuupdmbuxejyfck.supabase.co`、anon key 直書き
- 専用設定ファイル `member/js/supabase-config.js` は **`your-project-url` のまま放置・未使用**
