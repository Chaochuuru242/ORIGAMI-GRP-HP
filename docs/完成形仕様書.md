## 1. アプリ概要

### 1-1. 目的・解決する課題
AI を「稼ぐ力」に変えたい個人と、それを支援できる講師を、**サブスクと面談予約をワンストップで提供する会員制プラットフォーム**として接続する。決済・プラン管理・面談予約を運営の手作業に依存せず自動化する。

### 1-2. 対象ユーザー
| セグメント | 想定属性 |
|---|---|
| メイン | 副業・フリーランスでAI活用したい個人 / 中小企業の経営者・マネージャー / 大手企業の社員（業務効率化目的） / AI初学者・学生 / プロのクリエイター・マーケター |
| 年齢層 | 20代 / 30代 / 40代 |
| ITリテラシー | 中〜低（ChatGPT触ったことある程度〜操作はわかりやすくする必要あり） |

### 1-3. 技術スタック（確定）
| レイヤ | 採用技術 |
|---|---|
| フレームワーク | Next.js 15 (App Router) |
| 言語 | TypeScript 5.x |
| UIライブラリ | React 19 |
| スタイル | Tailwind CSS v4 |
| UIコンポーネント | shadcn/ui |
| 認証・DB・Storage | Supabase（@supabase/ssr 経由） |
| 決済（サブスク） | Stripe Subscriptions |
| 決済（面談・分配） | Stripe Connect Express |
| カレンダー連携 | Google Calendar API + Google Meet 自動発行 |
| メール送信 | Resend |
| Cron・定期処理 | Vercel Cron |
| ホスティング | Vercel |
| フォーム | React Hook Form + Zod |
| 状態管理 | Server Components 中心 + React Query（クライアント側必要時） |

## 2. 完成形の定義

### 2-1. 完成の条件（これら全てを満たして「完成」）
1. ✅ ユーザーが管理者の手を借りずにプラン購入できる（Stripe決済自動化）
2. ✅ ユーザーが管理者の手を借りずにプラン解約できる（自動更新停止）
3. ✅ プランごとの動画視聴制限が機能している
4. ✅ 動画ごとの視聴ができる（YouTube/Vimeo埋込）
5. ✅ 講師が運営の招待で登録でき、Stripe Connect で報酬受取が完了する
6. ✅ 講師が自分の予定（空き時間）を管理できる
7. ✅ ユーザーが講師に対してオンライン面談（60分）の申し込みと決済ができる
8. ✅ 動画にカテゴリを付与でき、ユーザーがカテゴリで絞り込み視聴できる
9. ✅ 学習プレイリストを管理者が作成・配布でき、ユーザーが順番に視聴できる

### 2-2. MVP の定義（最低限これがあれば完成と言える）
| # | 機能 | 理由 |
|---|---|---|
| MVP-1 | Stripe Subscriptions による プラン自動購入・解約 | 「完成」の核心 |
| MVP-2 | プラン別動画視聴制限（既存ロジック移植） | 既存資産 |
| MVP-3 | 動画一覧 / 詳細 / 視聴履歴 | 既存資産 |
| MVP-4 | カテゴリ管理（admin CRUD・単一カテゴリ） | 新規だが軽い |
| MVP-5 | 講師招待・登録（Stripe Connect Express連携） | 完成条件5 |
| MVP-6 | 講師の空き時間設定（カレンダーUI） | 完成条件6 |
| MVP-7 | 面談予約（決済・Google Meetリンク自動発行） | 完成条件7 |
| MVP-8 | 解約フロー（理由アンケート＋退会2段階） | 完成条件2 |

### 2-3. スコープ外（将来拡張・今回は実装しない）

- アフィリエイト・紹介プログラム

## 3. 技術スパイク結果

### 3-1. 既知の地雷・注意点

#### Stripe Connect
- 🔴 **国内 Connect は KYC が厳しい**：講師は本人確認書類・銀行口座・マイナンバーが必須
- 🔴 **Stripe審査NG履歴あり**：再申請時、前回の落ちた理由を確認しないと再度弾かれる可能性
- 🟡 **手数料**：プラットフォーム手数料に加えて Stripe基本 3.6% + Connect 0.25% + ¥7
- 🟡 **Express vs Standard vs Custom**：講師UX的に **Express** 一択

#### 面談予約システム
- 🔴 **タイムゾーン**：全予約を **UTC で保存**、表示時に locale 変換。ズレ事故防止
- 🔴 **ダブルブッキング防止**：DB トランザクション + ユニーク制約必須
- 🟡 **Zoom API は法人想定** → Google Meet（Calendar API 経由で自動生成）を採用

#### Next.js + Supabase
- 🟡 `@supabase/auth-helpers-nextjs` は deprecated。**`@supabase/ssr`** を使う
- 🟡 全テーブルに RLS 設定が必須

#### Stripe Webhook
- 🔴 ローカル開発：`stripe listen` CLI でフォワード
- 🔴 **冪等性**：`event.id` で重複排除しないとプラン2回付与の事故

#### shadcn/ui + Tailwind v4
- 🟢 特に地雷なし。日本語フォント（Noto Sans JP / Noto Serif JP）の登録のみ最初に実施

### 3-2. 推奨実装方法
- Stripe Webhook は Next.js の Route Handler（`app/api/stripe/webhook/route.ts`）で受信
- Stripe Connect は Express アカウント＋ `account_link` で講師を Stripe ダッシュボードへ誘導
- 面談予約のダブルブッキング防止は PostgreSQL の `EXCLUDE` 制約 or unique index on `(teacher_id, start_at)`
- メール送信は Resend の React Email テンプレート
- カレンダー UI は **react-big-calendar** または **@fullcalendar/react**
- 状態管理は Server Components 主体、リアルタイム性が必要な箇所のみ React Query

### 3-3. 人間側で事前に準備すべきこと

#### 🔴 高優先（これがないと開発が止まる）
1. **Stripe アカウント再申請の準備**（前回NG理由確認・特商法・プライバシーポリシー整備）※Stripe対応はユーザーが別途実施予定
2. **Google Cloud Console**：Calendar API + Meet API 有効化、OAuth 2.0 クライアントID取得、同意画面設定
3. **Resend アカウント開設**：送信元ドメイン認証（SPF/DKIM レコード追加）
4. **講師招待時の案内文**：「Stripe Connect 登録手順マニュアル」を運営側で用意

#### 🟡 中優先（並行で準備可）
5. Vercel アカウント + GitHub 連携
6. 本番ドメインの確定
7. **既存ユーザーデータ移行方針の決定**（profiles / videos / video_views を新DBに引き継ぐか、リセットするか）
8. 講師向けの利用規約・報酬規定（手数料率明記）

#### 🟢 低優先（後回しOK）
9. プレイリスト・カテゴリの初期コンテンツ整理
10. 面談機能リリース時のキャンペーン文言

### 3-4. リスク・不明点

| リスク | 対応方針 |
|---|---|
| Stripe審査再NG | フォールバック：PAY.JP マーケットプレイスを併記 |
| 既存ユーザー移行 | 「データ移行方針」を要決定として明記。デフォルト方針＝既存 profiles を新DBにコピー、決済情報は再登録依頼 |
| 講師KYC脱落率 | 講師オンボーディング画面で離脱対策（保存して再開可能なフォーム） |
| 開発期間 | 現実的に 2〜4ヶ月（フルタイム想定） |

## 4. デザインシステム

### 4-1. 参照元
既存の [styles.css](styles.css) と [member/styles/member-styles.css](member/styles/member-styles.css) からデザイントークンを抽出し、Tailwind CSS v4 の `@theme` ディレクティブに移植する。

### 4-2. デザイントークン（既存から継承）

#### カラー
| トークン名 | 値 | 用途 |
|---|---|---|
| `primary` | `#5B4B8A` | ブランドメインカラー（紫） |
| `primary-dark` | `#3F3366` | プライマリホバー・強調 |
| `primary-light` | `#F2EFFF` | プライマリ薄色背景 |
| `text-main` | `#1C1D21` | 本文・見出し |
| `text-muted` | `#5E6278` | 補足・キャプション |
| `bg-main` | `#FFFFFF` | メイン背景 |
| `bg-sub` | `#F9FAFB` | セクション背景 |
| `border` | `#E4E6EF` | 罫線・カード境界 |

#### タイポグラフィ
- 英数字：Inter
- 日本語：Noto Sans JP
- 見出し用セリフ（必要時）：Noto Serif JP

#### 形状
- カード角丸：12px (`--radius`)
- ボタン角丸：8px
- 画像フレーム角丸：12px
- 最大幅：1140px (`--max-w`)

#### シャドウ
- `shadow-sm`：`0 4px 12px rgba(0, 0, 0, 0.04)` — カードのデフォルト
- `shadow-md`：`0 12px 24px rgba(0, 0, 0, 0.08)` — ホバー時
- `shadow-primary`：`0 12px 28px rgba(91, 75, 138, 0.28)` — CTA ボタン強調

### 4-3. UI コンポーネントの基本方針
- **shadcn/ui を Primary に採用**。`npx shadcn@latest add button card dialog form input select tabs ...` で必要分だけ取り込む
- `globals.css` で上記カラー変数を定義し、`@theme` で Tailwind に注入
- ボタンバリアントは shadcn デフォルトを基準に、`primary` / `ghost` / `outline` / `link` の4種に統一
- 新規バリアント作成時はユーザーに確認

### 4-4. 画面別レイアウト構造

| 画面群 | 構造 |
|---|---|
| 公開LP（home / pricing / faq / login / register） | 上部固定ヘッダー＋フッター、コンテンツは中央寄せ max-w 1140px |
| 会員ダッシュボード系 | 左サイドバー（240px）＋メインコンテンツ（fluid）。モバイルではハンバーガー＋オーバーレイ |
| 動画詳細 | メイン2カラム（左：プレイヤー＋説明、右：資料・関連動画） |
| 講師ダッシュボード | 左サイドバー（メニュー：予約一覧・予定管理・売上・プロフィール）＋メイン |
| 管理画面 | 既存4タブ構造を踏襲（ユーザー管理・コンテンツ管理・分析・承認） |

### 4-5. レスポンシブ対応方針
- モバイルファースト
- ブレークポイント：Tailwind デフォルト（sm:640px / md:768px / lg:1024px / xl:1280px）
- サイドバーは lg 未満で非表示（ハンバーガー切替）
- テーブル系は md 未満でカード型に変換

### 4-6. アニメーション
- 過剰なアニメーションは禁止
- ホバー時の transform / shadow 変化のみ許可
- ページ遷移アニメーションは Next.js デフォルト（なし）

## 9. 名称定義

### 9-1. 用語集

| 用語 | 定義 |
|---|---|
| **会員 / メンバー** | プラットフォームに登録したユーザー全般（free含む） |
| **プラン** | サブスク契約の種類。`free` / `light` / `standard` / `premium` |
| **ロール** | システム権限。`user` / `adder` / `teacher` / `admin` |
| **講師 / Teacher** | 面談を提供する登録ユーザー。`role='teacher'` |
| **adder** | 動画を申請できるが管理者ではないロール |
| **admin** | システム管理者 |
| **コンテンツ** | 動画コンテンツ全般 |
| **カテゴリ** | 動画の分類軸（管理画面でCRUD・1動画につき1カテゴリ） |
| **プレイリスト** | 順序付きの動画コレクション |
| **面談 / Booking** | 講師との60分オンラインセッション |
| **空き時間 / Availability** | 講師が予約可能と設定した時間枠（60分単位） |
| **解約** | プラン購読停止（期間末まで利用可） |
| **退会** | アカウント削除（解約後に実行可） |
| **プラットフォーム手数料** | 面談料金から運営が徴収する割合 |

### 9-2. 命名規則

#### ファイル名
- **Reactコンポーネント**：kebab-case (`video-card.tsx`)

### 10-2. データフロー（主要ユースケース）

#### サブスク購入フロー
```
ユーザーが /pricing で「購入」クリック
  → POST /api/stripe/checkout（plan指定）
  → Stripe Checkout Session 作成
  → Stripe Hosted Page にリダイレクト
  → 決済完了
  → Stripe → POST /api/stripe/webhook (event: checkout.session.completed)
  → handler: profiles.plan / stripe_customer_id / stripe_subscription_id を更新
  → handler: メール通知（Resend）
  → ユーザーは success_url に戻る → /dashboard で新プラン反映
```

#### 面談予約フロー
```
ユーザーが /teachers/[id] で時間枠選択
  → POST /api/bookings/create
  → DBで availability の lock取得・bookings INSERT (status='pending')
  → POST /api/stripe/booking-checkout
  → Stripe Checkout Session（destination=teacher.stripe_account_id, fee=platform_fee）
  → 決済完了
  → Stripe → /api/stripe/webhook (event: checkout.session.completed)
  → handler: bookings.status を 'confirmed' に
  → handler: Google Meet リンク生成
  → handler: bookings.google_meet_url 更新
  → handler: ユーザー＋講師に確定メール送信
```

#### 解約フロー
```
ユーザーが /account/billing で「解約」
  → /account/cancel（理由アンケート）
  → POST /api/stripe/cancel
  → Stripe: subscription.update(cancel_at_period_end=true)
  → DB: profiles.cancel_at_period_end=true, cancel_reasons INSERT
  → 期間末到達
  → Stripe → /api/stripe/webhook (event: customer.subscription.deleted)
  → handler: profiles.plan='free', subscription_status='canceled'
  → メール通知
```

## 12. 開発ルール（Claude Code 向け）

### 12-1. 必ず守ること
1. 実装着手前に `docs/progress.html` を作成し各 Phase の完了率を更新
2. ハードコード禁止：プラン名・カテゴリ名・手数料率は `lib/constants.ts` または `platform_settings` テーブル経由
3. Supabase URL/Key は `.env.local` 経由のみ。HTML/JSへの直書き禁止
4. 新DBカラム追加時は `docs/reference-map.md` も更新
5. エラー解決後は `docs/error-log.md` に記録
6. 全テーブルに RLS を設定してから機能実装に進む
7. ローカルホスト確認 → ユーザー報告 → 次へ

### 12-2. やってはいけないこと
1. Stripe シークレットキー・Service Role Key を Client Components で読まない
2. `console.log` を本番コードに残さない
3. TypeScript の `any` を使わない
4. Webhook の冪等性を無視しない（必ず `event.id` で重複チェック）
5. 予約のダブルブッキング防止を DB制約に依存せずアプリ層だけで行わない
6. ユーザー入力を直接SQLに渡さない（Supabase SDK or RPC のみ使用）
